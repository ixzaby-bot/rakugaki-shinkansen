# らくがき新幹線 v0.2.0

2〜5歳児向けの、指で描いた線路を緑色のオリジナル新幹線が走るプロトタイプです。HTML / CSS / JavaScript / Canvasのみで動作し、外部ライブラリ・API・通信・広告・保存機能はありません。

## 公開先

- ゲーム: https://ixzaby-bot.github.io/rakugaki-shinkansen/
- GitHub: https://github.com/ixzaby-bot/rakugaki-shinkansen
- 公開するゲームのバージョン: v0.2.0。リリースのコミットは同名のGitタグから確認できます。公開後の検証記録は後続コミットで管理します。
- GitHub Pagesの公開元: `main` ブランチの `/ (root)`。

## 起動方法

PCでは `index.html` をブラウザで開くだけで遊べます。ビルドやインストールは不要です。

iPhone / iPadでは上記のゲームURLをSafariで開いてください。別リポジトリで公開する場合のGitHub Pages設定手順は次のとおりです。

1. このフォルダのファイルをGitHubリポジトリにpushします。
2. リポジトリのSettings → Pagesで、公開元を「Deploy from a branch」、ブランチを `main`、フォルダを `/ (root)` に設定します。
3. 発行されたURLをSafariで開きます。

相対パスのみを使っているので、リポジトリ名を含むURLでも動作する構成です。

## 今後の更新手順

1. 変更後に `node --check script.js` と `node tests/smoke.cjs` を実行します。
2. 仕様書・変更履歴・テスト記録を更新し、実機確認と自動検証を区別して記録します。
3. 変更をコミットし、`git push origin main` を実行します。Pagesが自動で再デプロイします。
4. ゲームのバージョンを更新する際は新しいタグを作成し、`git push origin <タグ名>` で送信します。既存タグを移動しないでください。
5. GitHubのActionsでPagesの完了を確認し、公開URLを再読み込みして動作を確認します。

## 操作方法

- 白い画面を指一本、またはマウスの左ドラッグでなぞります。
- 指を離すと線路が確定し、新幹線が自動で走り出します。
- 描いた線の細かなブレを補正し、先頭車・中間車2両・最後尾車の最大4両編成が走ります。短い線路では両数と大きさを自動調整します。
- 開いた線路は端で折り返します。始点の近くまで戻って描くと周回します。
- 既存の線路の端から描き始めるか、端に向かって描き終えると継ぎ足せます。両端を結ぶと周回線路にでき、別の2本をつなぐこともできます。
- 接続が成功すると接続箇所が短く光ります。走行中にも追加でき、走っている編成の位置は保たれます。
- 端から離れて描いた独立線路には新幹線が移動します。過去の線路は薄い色で残ります。走行対象ではない線路だけを伸ばした場合は、現在の線路を走り続けます。
- 「ぜんぶけす」で線路と車両を消し、最初から遊べます。
- 短すぎる線やタップでは新しい線路を作らず、以前の走行を継続します。

## 検証

Node.jsがある環境で `node --check script.js` と `node tests/smoke.cjs` を実行できます。自動テストはDOMとCanvasを模した環境で入力・走行計算を検証するもので、実際のブラウザ描画やSafari実機試験を代替しません。詳細は [テスト記録](docs/TEST.md) を参照してください。

## 既知の制約

- v0.1.1はユーザーの実機テスト全8項目で合格しています。端末・OS・ブラウザの詳細は報告されていません。v0.2.0の継ぎ足し操作・接続の見た目は実機未確認です。
- 接続許容距離は `script.js` の `CONNECT_RADIUS`（28 CSS px）で調整できます。近い候補が同距離（差0.5 px未満）の場合や同じ端点へ両端を接続する場合は、独立線路として扱います。
- 接続時に車両が急に増えたり大きくなったりしないよう、編成の両数・サイズを維持します。短い線路を伸ばしても両数は増えません。新しい独立線路を描くと長さに合わせて再設定します。
- 車両の中心は補正済み経路上を通りますが、極端な急カーブでは車体が線路からはみ出したり、車両同士が重なる場合があります。車体の衝突判定はありません。
- 線路は局所的に平滑化した細かい折れ線です。非常に急な折り返しでは2本のレールが重なることがあります。
- 全長100 CSS px以上で、終点が始点から24 CSS px以内の場合に閉じた線路と判定します。意図せず周回になる場合があります。
- 画面サイズ変更では描画時の元座標から毎回計算し、線路と編成を同じ倍率で中央に収めます。元の画面サイズへ戻すと元の大きさに戻ります。小さな画面では車両も小さく表示されます。
- 自己交差は描いた順序どおり走行します。線路途中への分岐・交差点の進路選択・閉路への追加接続はありません。
- 線路数・入力点数の上限は設けていません。長時間描き続けると端末によって重くなるため「ぜんぶけす」を使用してください。
- 画面端では車体が一部隠れます。タイトル・ボタン付近は表示と線路が重なる場合があります。
- リロードやページを閉じると描いた線路は失われます。

## 次の改善候補

2. 幼児の試遊で速度（現在70 CSS px/秒）、車両サイズ、ボタン配置を調整する。
3. 4両編成の見た目、平滑化の強さ、急カーブでの車体の重なりを実機で確認・調整する。
4. 大量入力時の点の間引きと描画負荷の改善を検討する。
5. 検証後に車両・背景・変身イラストの追加を検討する。
