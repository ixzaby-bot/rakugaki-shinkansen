# 仕様 v0.1.1

更新日: 2026-11-21

## 目的と範囲

2〜5歳児が指で描いた線路を新幹線が走るコア体験を検証する。全画面の白いCanvas、緑色のオリジナル新幹線（最大4両編成）、大きな消去ボタンを備える。図形認識、変身、背景テーマ、別車種の追加、線路の分岐・接続、課金、広告、セーブは対象外。

## 入力

- Pointer Eventsで指一本とマウス左ボタンを共通処理する。
- 有効な描画中は別のポインターを無視し、pointer captureで画面外への移動を扱う。
- touch-action: none、固定body、overflow/overscroll制御で描画中のスクロールを抑止する。
- client座標からCanvasの矩形位置を引く。2 CSS px未満の移動は採点しない。
- pointerupで確定。pointercancel / lostpointercaptureでは未確定線だけを破棄する。
- 24 CSS px未満の線は確定せず、既存の走行対象を変えない。

## 線路と走行

- 線路は2本のレールと14 CSS px間隔の枕木で描画する。
- 平滑化前の全長100 CSS px以上かつ両端の距離24 CSS px以内で両端を接続する。補正で閉路判定を変えない。
- 入力点列を約6 px以下の等間隔で再サンプリングし、Chaikin法（隣接点の1/4・3/4を結ぶ処理）を2回適用する。開路の始点・終点は保持し、閉路は循環して処理する。
- 描画中のプレビューも同じ補正を適用する。入力変更・サイズ変更時のみ再計算する。確定後はレール・枕木・車両すべてが同じ補正済み経路を使う。
- 最後の有効な線路を濃く、過去の線路を薄く表示する。新しい線路が確定したら編成を始点側に収めて配置する。
- 各区間の累積長と二分探索で位置を求め、70 CSS px/秒で走る。
- 開いた線路は編成全体が収まる走行範囲内で三角波状の距離計算により折り返す。閉じた線路は車両ごとの経路距離を全長で剰余処理して周回する。
- 自己交差でも入力順序を維持する。車両中心は必ず線分上にあり、曲率に応じた脱線判定はしない。
- requestAnimationFrameを使い、経過時間は最大50 msとして復帰時の大きなジャンプを防ぐ。
- 確定済み線路は別Canvasにキャッシュし、描画中の線路と車両だけ毎フレーム更新する。

## 編成

- 元の補正済み全長Lに対し、両数は `max(1, min(4, floor(L / 70)))`。280 px以上なら先頭車・中間車2両・最後尾車となる。
- 基本車両倍率は `min(1, L / 100)`。短い線では車両も縮小する。画面サイズ変更時は表示倍率をさらに掛ける。
- 車両中心の経路間隔は66×車両倍率、開路の両端余白は34×車両倍率。走行可能範囲は全長から両端余白と編成間隔の合計を引く。
- 各車両の位置は独立に経路距離から求め、前後6×車両倍率の点を結ぶ方向を角度とする。閉路の継ぎ目でも前後の点を循環参照する。
- 開路で折り返す際は移動方向だけを変更する。車両の順序・姿勢を反転させず、反対端の運転台が進行方向を向く。1両の場合は同じ姿勢のまま往復する。
- 両端の車両は運転台付き、中間車は窓付きとする。連結部分も経路に沿って描く。車体の接触・衝突は判定しない。

## サイズ変更と表示

- CSS寸法とCanvasピクセル寸法を分離する。devicePixelRatioは負荷抑制のため最大3。
- 各線路の確定時の補正済み元経路と、描画開始時の画面寸法を保持する。サイズ変更は常に元経路から縦横同率・中央配置で再投影する。変換結果を元経路へ書き戻さない。
- 編成両数は元の経路長から決め、画面回転で増減させない。走行範囲に対する進捗と方向を保持し、車体と間隔も線路と同じ比率で拡縮する。
- 描画途中の元点列も変更せず保持する。サイズ変更後の入力は逆変換して元点列へ追加する。異なる画面サイズで追加した線路も、それぞれの描画時寸法から計算する。
- タイトルと案内は入力を遮らず、消去ボタンだけが操作領域を持つ。セーフエリアを考慮する。

## 管理

仕様の判断をこの文書に記録する。初版の追加判断は「最後の線路を走行」「短すぎる線は無視」「閉路の距離閾値」「サイズ変更時の同率変換」。保存・外部通信は行わない。

v0.1.1では編成位置を走行方向から独立させ、折り返しでの瞬間移動を防ぐ。サイズ変更による縮小の原因は前回の変換済み座標への累積変換だったため、元経路からの再投影に置き換えた。v0.1.0の履歴・タグは保持する。
