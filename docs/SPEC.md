# 仕様 v0.2.1 — 複数線路・複数編成

更新日: 2026-11-21

今回の指示書はv0.2.0を目標としているが、既存の公開済みv0.2.0（1編成版）を保持するため、ユーザー承認によりv0.2.1として実装する。新しい指示書を優先し、前版の「1編成のみ」「異なる2本の統合」を変更する。

## 目的・基本操作

- 独立線路1本につき編成を1つ追加し、以前の線路と編成を残す。
- 既存の開路の端へ継ぎ足す場合は編成を追加せず、同じ編成が延長区間も走る。
- すべての編成を同時に更新する。描画中も走行し、接続専用モードは設けない。
- HTML / CSS / JavaScript / Canvasのみの静的構成。外部API・有料サービス・保存なし。

## 入力・平滑化

- Pointer Eventsで指一本とマウス左ボタンを共通処理。pointer capture、pointercancel、lostpointercaptureに対応。
- touch-action: none、固定body、overflow / overscroll制御で描画中のスクロールを抑止。
- 入力のclient座標からCanvas矩形位置を引く。移動2 CSS px未満は追加しない。
- 指を離して確定し、描画開始時の基準座標で全長24 px未満の線やタップでは線路・編成を生成しない。
- 約6 px以下の等間隔再サンプリングとChaikin法2回で局所平滑化。開路端点を保持する。
- 描画プレビューと確定経路で同じ補正方法を使う。確定後のレール・枕木・車両は同じ補正済み経路を参照する。
- 独立線路は補正前の全長100 px以上かつ両端距離24 px以内で閉路化する。

## データ構造

- `tracks[]`: `id`、表示経路のpoints / cumulative / length / closed、元経路source、基準画面寸法、表示倍率scale。
- `tracksById`: 線路IDから線路オブジェクトへのMap。毎フレームの編成からの参照に使う。
- `trains[]`: `id`、`trackId`、`type: 'hayabusa'`、`distance`、`direction`、`speed`、`carCount`、`baseSize`。
- `distance`は編成の経路上の移動量、`speed`はCSS px/秒。初期速度は70。両数と基準車体サイズは編成に保持する。
- 線路と編成のIDは独立した連番で、継ぎ足し・閉路化・リサイズでも維持する。線路1本につき編成1つ。
- 配列順序ではなくtrackIdで対応づける。追加順を入れ替えても走行を維持する。
- 全消去で配列・Map・描画一時データ・演出・時間状態・ID連番を初期化する。個別削除は実装しない。

## 端点接続

- 確定時に、新しく描いた両端と既存の開路の両端を現在の画面座標で比較する。途中点・閉路は候補にしない。
- 許容距離は `CONNECT_RADIUS = 28` CSS px。画面回転後も画面上の同じ距離で判定する。
- 最短距離の有効候補を選ぶ。最短と次点の差が0.5 px未満なら曖昧とする。
- 曖昧な候補、同一端点への両端接続、異なる2本への同時接続は、独立線路として生成する。既存線路・編成は変更しない。
- 始点→始点、始点→終点、終点→始点、終点→終点の全パターンで必要に応じて新規区間を反転し、既存経路の向きを保って結合する。
- 端点をスナップし、新しい区間の接続付近だけ最大16 pxを三次ベジェで接線補間する。既存経路は再平滑化しない。
- 同じ開路の反対側の端点同士を結ぶ場合は閉路化する。新規線の表示長40 px未満、描画範囲の対角距離28 px未満、結合後の全長100 px未満では誤閉路化を避け、独立線路として処理する。
- 非有限値・経路長が増えないなどの不正な結合も独立線路へフォールバックする。
- 接続成功時は各接続点に0.6秒の放射状の光を描画する。入力領域を遮らない。

## 接続後の走行継続

- 対象線路と編成のIDを変更せず、他の線路・編成には触れない。
- 始点側に追加した区間の長さを走行距離へ加算し、全車両の中心位置を維持する。
- 閉路化時も現在の進行方向を維持し、逆向きなら逆周回する。
- 両数・車体サイズ・経路上の間隔を保持する。短い線路を伸ばした場合も編成が突然増えないよう、増結は行わない。
- 接続時の画面寸法と表示座標を新たな元経路にする。車体の基準サイズも同じ座標系に合わせる。

## 車両・アニメーション

- 新規線路の補正後長Lに対し、両数は `max(1, min(4, floor(L / 70)))`、車体倍率は `min(1, L / 100)`。通常は先頭車・中間車2両・最後尾車の4両。
- 車両間隔は66×車体倍率、開路両端の余白は34×車体倍率。画面変更時は表示倍率も掛ける。
- 累積経路長の二分探索で各車両の位置を個別に算出。前後6×車体倍率の点から方向を求め、閉路継ぎ目は循環参照する。
- 開路は編成が収まる範囲で折り返し、編成順序や姿勢を突然反転しない。閉路は経路長の剰余で周回する。
- 1つのrequestAnimationFrameで全編成を更新・描画する。経過時間は最大50 msとし、非表示復帰時に時刻をリセットする。
- 確定線路は別Canvasへキャッシュし、線路変更・画面変更時のみ再描画。累積経路長も毎フレーム再計算しない。
- すべての線路を同じ濃さで表示する。描画領域を圧迫する追加UIは設けない。

## 画面サイズ変更

- CanvasはCSS寸法とバッファ寸法を分離し、devicePixelRatioは最大3。
- 元経路から毎回、縦横同率・中央配置で再投影する。変換済みの表示点へ累積変換を掛けない。
- 全編成の走行範囲に対する進捗と方向・IDを維持し、線路と車体を同じ倍率で拡縮する。
- 描画途中の点も元座標で保持し、サイズ変更後の入力を逆変換して追加する。
- safe-area、100dvhと100%のフォールバックを維持する。

## 対象外・制約

こまち・車種選択UI、走行音、異なる2本の統合、線路途中への接続、分岐器、交差点の進路選択、同一線路上の複数編成、衝突判定、個別削除、らくがき変身は対象外。極端な急カーブや交差点では車体が重なり得る。

編成数の上限は設けない。5編成と10編成の自動テストを行い、モック処理時間・ブラウザ確認・実機性能を区別して記録する。最終完成判定はユーザーのiPhone / iPad実機テスト後に行う。
